# 배포와 운영

CloudWatch Alarm Generator는 프론트엔드, 조회 백엔드, 자격증명 브로커로 구성됩니다. 이 문서는 특정 계정이나 배포 ID에 의존하지 않는 공통 배포 절차만 설명합니다.

## 구성

```text
브라우저
  │
  ▼
CDN
  ├─ 정적 스토리지 → 프론트엔드
  └─ /api/* → 조회 백엔드
                 │
                 ▼
            자격증명 브로커
                 │
                 ▼
          고객 계정 읽기 전용 세션
```

- **프론트엔드**: React/Vite 정적 파일을 빌드해 정적 스토리지와 CDN으로 제공합니다.
- **조회 백엔드**: Slack 인증, 리소스 조회, AI 변환·추천·점검을 처리합니다.
- **자격증명 브로커**: 사내 사용자와 활성 고객 계정을 확인한 뒤 읽기 전용 임시 세션을 발급합니다.

## 프론트엔드 배포

현재 환경에 연결된 배포 스크립트를 실행합니다.

```bash
npm run deploy:web
```

이 명령은 프로덕션 빌드, 정적 파일 업로드, CDN 캐시 무효화를 수행합니다. 배포 전에 변경 사항을 커밋하고 `npm run build`를 통과시키는 것을 권장합니다.

## 조회 백엔드 배포

```bash
deploy/deploy-backend.sh <FUNCTION_NAME> <REGION>
```

백엔드는 `server/*.mjs`만 패키징합니다. 자격증명 브로커 코드를 조회 백엔드에 섞어 배포하지 않습니다.

최초 인프라 생성이나 구성 변경은 `deploy/backend.yaml`과 관련 설정 스크립트를 사용합니다.

## 주요 환경변수

| 이름 | 용도 |
|---|---|
| `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET` | Slack OAuth 로그인 |
| `SESSION_SECRET` | 로그인 세션 쿠키 보호 |
| `APP_BASE_URL` | 애플리케이션 기본 URL과 OAuth 콜백 구성 |
| `SLACK_TEAM_ID`, `ALLOWED_EMAIL_DOMAIN` | 허용 사용자 범위 |
| `BROKER_API_URL` | 자격증명 브로커 API 주소 |
| `BEDROCK_MODEL_ID` | AI 기능에 사용할 모델 |
| `FEEDBACK_TOPIC_ARN` | 오류 신고 알림 토픽 |
| `ALLOWED_ORIGIN` | 허용할 프론트엔드 오리진 |

실제 값과 시크릿은 코드나 문서에 기록하지 않고 배포 환경의 보안 설정에서 관리합니다. 환경변수 전체를 덮어쓰는 명령은 기존 값을 지울 수 있으므로 변경 전에 현재 구성을 확인합니다.

## 자격증명 브로커

자격증명 브로커는 조회 백엔드와 별도로 운영합니다.

1. Slack 로그인 정보로 사내 사용자를 확인합니다.
2. 요청한 계정이 허용된 활성 고객인지 확인합니다.
3. 고객 계정의 크로스어카운트 역할로 임시 세션을 발급합니다.
4. 세션 정책으로 읽기 전용 권한을 강제합니다.
5. 임시 자격증명은 조회 백엔드에서만 사용하며 브라우저로 전달하지 않습니다.

브로커 소스와 세부 운영 설정은 이 저장소에 포함하지 않습니다. 시크릿과 내부 인프라 정보는 별도의 비공개 운영 환경에서 관리합니다.

## 배포 후 확인

- 프론트엔드가 최신 정적 파일을 제공하는지 확인합니다.
- 백엔드 상태 확인 API가 정상 응답하는지 확인합니다.
- Slack 로그인과 로그아웃이 정상 동작하는지 확인합니다.
- 테스트 계정에서 읽기 전용 리소스 조회가 가능한지 확인합니다.
- 알람 생성 CLI에 허용되지 않은 명령이 없는지 확인합니다.
- CloudWatch API 파라미터 검증이 통과하는지 확인합니다.

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 계정 연결 실패 | 로그인 세션, 브로커 주소, 활성 고객 등록 상태 |
| 백엔드 시작 실패 | 올바른 백엔드 패키지를 배포했는지 확인 |
| 일부 리소스 조회 실패 | 고객 읽기 전용 역할의 Describe/List 권한 확인 |
| 화면 변경이 보이지 않음 | CDN 캐시 무효화 완료 후 브라우저 새로고침 |
| AI 기능 실패 | 모델 설정, 백엔드 실행 역할, 리전 지원 여부 확인 |

## 보안 체크리스트

- [ ] 로그인하지 않은 사용자는 보호된 API를 호출할 수 없다.
- [ ] 고객 계정 세션은 읽기 전용으로 제한된다.
- [ ] 액세스 키, 시크릿 키, 세션 토큰이 로그·응답·코드에 남지 않는다.
- [ ] 고객 계정 ID와 내부 배포 식별자를 문서에 기록하지 않는다.
- [ ] 프론트엔드에는 AWS 자격증명이 존재하지 않는다.
- [ ] 브로커와 조회 백엔드를 서로 다른 배포 단위로 유지한다.
